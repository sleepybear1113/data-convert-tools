# 需求、默认规则与待补输入

本文是项目实现时的需求基线。`README.md` 负责构建和使用说明，本文负责解释功能边界、默认交互和兼容策略，避免不同阶段采用互相矛盾的假设。

## 1. 已确认的产品决策

| 项目 | 已确认决策 |
| --- | --- |
| DBF 首版范围 | 样本兼容优先，并完整覆盖 `C/N/F/Y/D/L/I/T/B`；NULL 和 `_NullFlags` 为基础能力 |
| SQL 权限 | 查询为主，但允许 `INSERT/UPDATE/DELETE/DDL` 和事务 |
| 表格编辑 | 首版结果表格只读，不支持单元格编辑、增删行和撤销 |
| 工作区持久化 | 首版以导出文件保存，刷新后工作区清空，不引入自动恢复 |
| 目标规模 | 通常不超过约 10 万行或 100MB，按中小文件优化 |
| Excel | 读取和写入统一使用 SheetJS CE 0.20.3 |
| CSV | 使用 Papa Parse，并单独处理编码和类型推断 |
| DBF 默认编码 | 新 DBF 默认 GBK；DBF→DBF 跟随源编码，其他格式沿用本文默认规则 |
| 数值策略 | 保真优先；高精度 N/F、Y 和超安全范围整数使用十进制文本，SQL 计算时显式 CAST |
| 浏览器 | 只要求最新 Chrome/Chromium 内核桌面浏览器 |
| 测试样本 | 当前 DBF 已脱敏，可作为工程内部自动测试样本 |
| Java/外部验收 | 工程不包含 Java 或外部验收任务，最终验收由用户在其他工具中自行完成 |
| Node.js | 始终通过 `D:\Softwares\NodeJs\node-v24.21.0` 下的绝对路径构建 |
| npm | 项目 `.npmrc` 使用 `https://registry.npmjs.org/`；镜像的 Playwright 包同步不一致，因此改用官方源，不修改其他项目配置 |

## 2. 实际 DBF 样本揭示的硬性要求

仅检查了文件头和字段描述，没有把业务记录写入文档或测试输出。

| 属性 | 样本情况 |
| --- | --- |
| 文件版本 | Visual FoxPro `0x30` |
| 文件大小 | 当前脱敏版本为 3,049 字节 |
| 头部记录数 | 当前脱敏版本为 1，以头部为准，不以文件名中的数字为准 |
| 字段描述数 | 45 |
| 业务字段 | 44 个，全部为 `C` |
| 系统字段 | `_NullFlags`，类型 `0` |
| 可空字段 | 多个业务字段带 `0x02` 标志 |
| Language Driver | `0x7A`，对应简体中文代码页 936，按 GBK 处理并允许人工覆盖 |
| Header Length | 1,736 字节 |
| Record Length | 1,313 字节 |
| 字段描述结束位置 | 1,472 字节处的 `0x0D` |
| 描述结束到记录区之间 | 263 字节，当前样本全为零 |
| 文件结束标志 | 当前脱敏文件未包含额外 `0x1A`，最后字节为记录末尾的 `0x00`；Writer 仍按规范写出 `0x1A` |

### 2.1 Reader 必须遵守

1. 第一条记录必须从 `headerLength` 定位，不能假设记录紧跟字段描述结束符。
2. `_NullFlags` 是系统字段，不应作为普通业务列展示，但解析 NULL 时必须使用它。
3. 字段 flags、系统字段标志和原始字段顺序需要保留。
4. 直接 DBF→DBF 时保留头部附加字节；新文件写入以现有样本、VFP 格式规则和二进制测试确定布局。
5. 记录删除标志独立于字段值解析。
6. 编码自动识别只提供默认值，必须提供预览和手工切换。
7. 不把字符形式的日期或编码字段仅按名称自动改成其他 DBF 类型；源为 DBF 时优先保留原字段类型。

### 2.2 Writer 必须遵守

1. 记录数在写文件头前确定，流式记录接口同时携带 `recordCount`。
2. 写入字符字段时按目标编码后的字节数校验，而不是 JavaScript 字符数。
3. NULL 位图与业务字段同步生成，不能只写出空字符串来模拟 NULL。
4. 不支持静默截断、隐式精度损失或把无法编码的字符替换为 `?`。
5. 文件记录布局、记录删除标志、字段描述结束符和文件结束标志需要独立测试。
6. JS 读写回环用于内部一致性验证；用户使用其他工具进行的外部验收不属于本工程任务或构建依赖。

## 3. 功能边界与默认行为

### 3.1 文件导入

- DBF：导入为一个 SQLite 工作表，同时保存 DBF 来源元数据。
- SQLite：读取已有数据库并保留其中的工作表；应用内部元数据表默认隐藏。
- XLSX：选择一个工作表、表头行和需要导入的列；不同工作表可分别导入。
- CSV：确认编码、分隔符和表头后再导入。
- 源文件只读，导入操作不修改用户原始文件。
- 导入前显示 Schema、抽样数据和诊断；确认后才写入工作数据库。

### 3.2 类型推断

默认配置：

```text
模式：抽样 1,000 行，可切换全量扫描
前导零：保留为文本
空字符串：不自动等同于 NULL
布尔值：true/yes/y 与 false/no/n，可在界面扩展
日期：优先 YYYY-MM-DD、YYYY/MM/DD，不猜地区性格式
混合类型：给出警告并回退到兼容类型，通常是 TEXT
```

推断结果是可修改建议，不是不可更改的事实。

对于身份证号、考生号、编码、邮编等标识字段，即使全部是数字也默认保留前导零。全量扫描仍不能证明未来值一定是数值，因此导出前允许人工指定为文本。

### 3.3 DBF 与 SQLite 默认类型映射

| DBF 类型 | SQLite 工作值 | 保真和导出规则 |
| --- | --- | --- |
| `C` | `TEXT` | 保存原始字节长度、编码和 NULL 元数据 |
| `N/F` | 普通精度使用数值；高精度列使用十进制文本 | 超过常见安全精度时保护原值并提示；导出恢复长度和小数位 |
| `Y` | 十进制文本，内部可配合缩放 `BigInt` | 不经过浮点数，恢复货币格式 |
| `I` | 安全范围内使用 `INTEGER`，更大值使用文本 | 避免 JavaScript `Number` 精度损失 |
| `L` | `0/1/NULL` | 导出恢复逻辑值 |
| `D` | `YYYY-MM-DD` 文本 | 不做 UTC 或本地时区转换 |
| `T` | `YYYY-MM-DD HH:MM:SS.SSS` 文本 | 按无时区日期时间处理 |
| `B` | `REAL` | 以 Visual FoxPro Double 语义处理 |

高精度列转为文本时必须在字段映射和诊断中可见，SQL 需要数值计算时由用户显式 `CAST`。字段映射允许人工覆盖默认策略；从查询结果创建 DBF 时，以用户确认的目标类型为准。

### 3.4 SQL 工作区

- 使用真实 SQLite 引擎，不用正则表达式模拟 SQL。
- `Ctrl+Enter` 执行选中文本；没有选区时执行当前语句。
- 另提供“运行脚本”入口处理多条语句，多语句结果按语句分别返回。
- 查询结果在 Worker 内物化，通过 `resultId` 分页读取和导出。
- 导出当前查询结果时复用已有 `resultId`，不重复执行 SQL；导出不会释放仍在页面使用的结果。
- 查询结果表格只读，页面只保留当前页。
- 执行 SQL 修改后将工作区标记为未保存；导出保存后清除该状态。
- SQL 错误不清空上一次成功结果，新错误显示在诊断区域。
- 执行 DDL/DML 后刷新表名、列名补全。
- 不使用脆弱的正则表达式判断“SQL 是否安全”；用户执行修改语句的意图在界面中明确表达。
- 同一 Worker 同时只执行一个会修改工作区的任务，避免导入、导出和 SQL 并发产生不一致。

### 3.5 结果展示

- 默认每页 200 行，可调整。
- 大文本、二进制值、NULL 和空字符串应有不同显示方式。
- `bigint`、高精度 decimal 和日期字符串不在 UI 中强制转为 `Number` 或 `Date`。
- 不为了展示而加载整个结果集。
- 首版不提供结果单元格编辑、行新增、行删除和撤销。

### 3.6 导出

默认采用严格模式：

- 字段名冲突、DBF 超长、编码失败、精度溢出等问题先显示错误。
- 用户明确切换兼容模式后，才允许自动改名、扩大字段或截断。
- 每次兼容降级都必须生成可定位到列/行的诊断。
- 零列不能导出为表格文件。
- 导出成功后显示文件名、记录数、列数和警告数。

数据来源与 SQLite 导出语义：

| 数据来源 | DBF/XLSX/CSV | SQLite |
| --- | --- | --- |
| 当前查询 | 导出查询列和行 | 创建只含查询结果表的新 SQLite 文件 |
| 当前表 | 导出当前表 | 可创建只含该表的新 SQLite 文件 |
| 整个工作区 | 不适用 | 导出完整工作数据库 |

SQLite 导出提供“包含转换元数据”选项，默认开启：

```text
元数据表：__dct_metadata
界面：默认隐藏内部表
作用：保留 DBF 类型、长度、编码等，便于再次转回
关闭：得到更干净的数据文件，但不能保证完整恢复 DBF 细节
```

其他默认导出规则：

- DBF：新文件默认 GBK；DBF→DBF 跟随源编码，用户可在导出前修改。
- XLSX：默认单工作表，工作表名可编辑；SheetJS 不负责重新计算公式。
- CSV：默认 UTF-8 with BOM，可切换 UTF-8、GBK、分隔符和换行符。
- 文件保存：首版使用浏览器下载，不要求 File System Access API。

## 4. 默认交互补充

以下逻辑不需要额外产品决策，直接作为首版一致性规则：

1. 工作区存在未导出修改时，关闭或刷新页面前显示浏览器原生离开警告。
2. 新任务开始时禁用会产生冲突的导入、执行和导出按钮，并显示当前阶段。
3. 任务进度使用“已处理记录数/总记录数”；总数未知时只显示已处理数，不显示虚假百分比。
4. 首版不显示不可验证的“已取消”状态；只有引擎真正停止后才算取消成功。
5. 所有失败统一返回错误码、可读消息、位置信息和可选详情，不只弹出 `Error` 文本。
6. 列名冲突使用稳定的 `_2`、`_3` 后缀；同一输入重复转换得到相同结果。
7. SQL 标识符由程序生成时一律正确转义双引号，不直接拼接未转义表名。
8. 文件下载名会过滤路径分隔符和控制字符，避免把用户输入当作文件路径。
9. 诊断信息可以复制，错误报告不包含完整业务记录，避免无意泄露敏感数据。
10. 原始文件、全量行数据、Workbook 和 SQLite 句柄不进入 Pinia 深度响应式状态。

## 5. 第三方依赖边界

### 5.1 已写入 `package.json`

```text
运行：Vue、Pinia、Naive UI
SQL：sql.js、CodeMirror、@codemirror/lang-sql
Excel：本地 SheetJS xlsx-0.20.3.tgz
CSV：papaparse
编码：iconv-lite（浏览器端 buffer/string_decoder 最小 polyfill）
数值：decimal.js
构建：Vite、TypeScript、vue-tsc
测试：Vitest、Playwright
```

依赖版本在 `package.json` 中固定，实际安装结果已经通过绝对 Node/npm 启动器写入 `package-lock.json`。

### 5.2 首版使用浏览器原生能力，不额外加库

- 文件读取：`File`、`ArrayBuffer`。
- 文件下载：`Blob`、对象 URL，不引入 FileSaver。
- 大整数：`BigInt`。
- Worker：原生 Web Worker 和类型化消息协议。
- 标识符唯一 ID：优先 `crypto.randomUUID()`，不引入 UUID 库。
- 日期：DBF 日期按日历值处理，不引入 Day.js/Luxon 代替二进制转换。

### 5.3 暂缓依赖

| 依赖 | 何时再考虑 |
| --- | --- |
| Comlink | Worker 调用明显增加且手写消息关联成为维护负担时 |
| 官方 SQLite WASM/wa-sqlite | 明确需要 OPFS、自动恢复或更大文件时 |
| AG Grid/Tabulator | 内置只读分页表格无法满足实际交互时 |
| StreamSaver | 出现全内存 Blob 无法承载的导出文件时 |
| Zod | 外部配置或 Worker 消息需要更复杂运行时 Schema 校验时 |

### 5.4 工程规范依赖

ESLint、Prettier 和对应 Vue/TypeScript 插件可在功能实现阶段作为开发依赖补充。它们不参与运行时，不在当前未安装阶段增加无用配置。

## 6. 构建前最终确认

当前没有需要等待的需求或环境输入：

1. 当前 DBF 已脱敏，可用于工程内部测试；长期自动测试仍应保留最小二进制夹具，避免测试只依赖一个样本。
2. `C/N/F/Y/D/L/I/T/B` 均为首版需要支持的类型，不再等待其他 JavaDBF 样本。现有样本覆盖 VFP `0x30`、C 和 NULL，其余类型按格式规则、预期字节夹具及读写测试实现。
3. 新 DBF 默认 GBK；DBF→DBF 跟随源编码。SQLite 使用其内部 UTF 编码，XLSX 由 SheetJS 处理 Unicode，CSV 默认 UTF-8 with BOM，并保留编码选项。
4. 只针对最新 Chrome/Chromium 内核桌面浏览器，不承担 Firefox、Safari 或旧浏览器兼容工作。
5. 最终外部工具验收由用户在工程外完成，不创建 Java 项目、外部验收脚本或相关完成门槛。
6. 首次 npm 安装已生成项目本地 `node_modules/` 和 `package-lock.json`；Playwright Chromium 已作为独立步骤下载到项目 `.cache/` 中。
7. 所有 Node/npm 命令继续使用绝对路径，不修改系统 PATH、其他项目环境或全局 npm 配置。

## 7. 首版完成标准

1. 当前脱敏样本的 44 个业务字符列、1 条记录和中文能够正确读取；NULL、EOF 和其他边界由独立二进制夹具覆盖。
2. 直接回写样本时保留原字段类型、长度、flags、头部附加区域和记录顺序。
3. `C/N/F/Y/D/L/I/T/B` 均有二进制边界测试、读写回环测试及导出校验，不依赖工程外验收才能运行测试。
4. DBF/XLSX/CSV 可进入 SQLite，SQL 修改后 Schema 和补全保持同步。
5. 查询结果分页展示，页面不会一次性接收全量结果。
6. 当前表和查询结果可按约定导出 DBF/XLSX/CSV；SQLite 导出语义符合上表。
7. 所有数据损失都由诊断系统显式呈现。
8. 生产构建不依赖运行时外部 CDN，刷新前未保存状态有明确提示。
